## 架构边界

| 需求 | 本次核查与边界 |
| --- | --- |
| 服务不混在一起 | web/admin/agent/worker 四独立进程；候选及公网跨服务路由拒绝已测 |
| 多租户隔离 | 同一 SaaS 数据库内 RLS 逻辑隔离，独立 tenant/platform/resolver 运行角色；不是每代理商一台物理数据库 |
| 代理商自主经营 | 总部审核/社区审核路由关闭；私有剧总部紧急操作拒绝；代理商可自行上/下架、修改私有媒体和计划 |
| 公共池与私有内容 | 公共内容和租户私有内容有独立归属，租户使用与权益受控；真实数据库跨租户及公共内容测试覆盖 |
| 可迁移部署 | IP 网关与磁盘 S3 是环境层；核心运行参数、数据库、Redis、对象存储和品牌/商店映射保持外置。换正式服务器不应另写业务系统 |
| 多用户一致性 | 并发购买幂等、余额、权益、RLS、worker 抢占、客户端过期响应保护见并发报告；没有承诺单机支持任意用户数 |
| 外部集成 | 支付、AdMob、Google/Apple 登录、推送等未配置项保持关闭，不能把关闭态或替身测试说成真实外部验收 |

正式海外开放还需要域名、CDN、监控告警、商店/广告配置和签名，以及真实规模的持续容量与故障演练。临时服务器上线成功不等于这些运营条件已具备，也不等于所有可能状态绝无 Bug。
