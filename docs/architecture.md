# 技术架构

## 技术选型

- 服务端：TypeScript、NestJS、Fastify。
- 管理后台：React、Vite、Ant Design；总后台和商家后台共用一套工程。
- 数据：PostgreSQL、Redis、异步任务队列。
- 媒体：S3 兼容对象存储、全球 CDN、签名播放 URL。
- 可观测性：结构化日志、指标、错误跟踪和审计日志。

旧 PHP/FastAdmin 项目不作为新服务端运行基础。这样可以彻底移除加密核心文件、外部授权上报、无鉴权写接口和固定采集服务。

## 边界

```text
H5 / Android / iOS ── CDN ── 视频对象存储
         │
         └── API 网关 ── NestJS API ── PostgreSQL
                                ├────── Redis
                                └────── 异步任务 Worker

总后台 / 商家后台 ──────────────┘
```

API 只返回播放授权和签名 URL，不转发视频文件。峰值在线观看流量主要由 CDN 承担，业务 API 可按实例水平扩容。

## 多租户隔离

1. 公网用户请求通过平台维护并已验证的域名绑定解析 `tenant_id`。
2. 商家员工的访问令牌固定绑定一个 `tenant_id`，后端忽略普通客户端提交的租户字段。
3. 平台员工进入商家视角必须持有平台权限，并产生进入、退出和业务操作审计。
4. 仓储层默认注入租户条件；跨租户查询只能调用单独的平台仓储接口。
5. 数据库索引以 `tenant_id` 开头；高风险表增加 PostgreSQL 行级安全策略作为第二道隔离。

## 模块顺序

1. 租户、域名、账号、会话、RBAC、审计。
2. 内容、剧集、翻译、审核、公共内容授权。
3. 用户、设备、播放权益、历史、收藏和社区互动。
4. 商品、价格、订单、支付适配、账本、提现和异常退款。
5. 营销、消息、推送、客服工单、导入导出和白标构建。

## 部署阶段

- 初期：单区 API/Worker、小规格 PostgreSQL 与 Redis、对象存储和 CDN。
- 增长：API/Worker 多实例、托管数据库高可用、Redis 高可用、独立任务队列。
- 峰值：按区域接入 CDN，API 自动扩容，数据库读副本；播放事件异步聚合，避免直接写热点表。
