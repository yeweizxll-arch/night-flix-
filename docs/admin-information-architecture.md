# 短剧 SaaS 总后台与商家后台信息架构

## 1. 目标与边界

本后台用于约 20～30 个商家的多租户短剧 SaaS。总后台和商家后台共享一套前端工程、组件库和权限框架，通过登录身份、租户范围与权限点动态生成菜单、路由和页面操作。两类后台可使用独立入口域名，但不维护两套代码。

核心原则：

- 所有业务数据强制带 `tenant_id`；商家账号只能访问当前商家数据，不能通过修改请求参数跨租户访问。
- “能看到菜单”和“能调用接口”是两层控制；后端接口必须再次验证角色、权限点、租户范围和数据状态。
- 总后台可治理全平台，但普通平台员工默认不能修改商家资金、用户资产或支付配置；特殊操作必须单独授权并留下审计记录。
- 列表、详情、导出、审核、配置、资金操作分别授权，不把“查看”权限等同于“编辑”权限。
- 菜单简洁，低频能力收进二级页面、详情抽屉或“更多操作”，仪表盘只展示决策所需指标和待办。

## 2. 入口与上下文

### 2.1 后台入口

- 总后台：独立管理域名，仅平台账号可登录。
- 商家后台：平台统一商家入口；可选支持从商家独立后台域名进入。
- 同一前端构建产物根据登录上下文加载菜单；平台账号和商家账号不能在同一会话中静默切换身份。
- 平台员工如需查看某商家数据，必须使用“进入商家视角”功能，页面持续显示醒目的商家名称和只读/可操作状态，并记录进入、退出和所有操作。

### 2.2 页面布局

- 左侧：按权限生成的两级菜单。
- 顶部：当前商家/平台标识、环境标识、待办、站内消息、语言、个人中心。
- 内容区：面包屑、页面级筛选、主操作按钮、数据表格或表单。
- 全局商家选择器只对获授权的平台岗位开放；切换后清空旧页面缓存和筛选条件。

## 3. 角色与权限模型

### 3.1 平台角色

| 预置角色 | 默认职责 | 关键限制 |
| --- | --- | --- |
| 平台超级管理员 | 创建商家、分配平台角色、平台全局配置、紧急处置 | 高风险操作仍需二次确认和完整审计 |
| 平台运营 | 商家资料、到期时间、域名、品牌与版本发布、公共运营位 | 无资金审批和系统安全权限 |
| 公共内容管理员 | 总部公共内容库维护 | 不审核或干预代理商私有剧及社区内容 |
| 平台财务 | 平台通道订单、对账、提现审核、线下打款确认、后台退款 | 无内容发布和账号权限管理 |
| 平台客服 | 工单协助、用户/订单只读查询、账号问题处理 | 不可直接改余额、积分、会员和支付状态 |
| 安全审计员 | 审计日志、登录事件、导出记录、风险事件只读 | 不可编辑业务数据或清除日志 |

平台角色均可由超级管理员复制并自定义权限。除超级管理员外，不提供隐含的“全平台全部权限”。

### 3.2 商家角色

| 预置角色 | 默认职责 | 关键限制 |
| --- | --- | --- |
| 商家所有者 | 商家配置、员工、支付、内容、营销和财务全权 | 不能修改平台分配的授权与到期状态 |
| 商家管理员 | 日常综合管理 | 默认不能查看完整支付密钥或变更所有者 |
| 内容运营 | 剧目、剧集、分类、多语言内容、评论/弹幕 | 无支付、提现和员工权限 |
| 财务 | 订单、对账、平台代收余额、提现申请、退款详情 | 无内容发布和营销群发权限 |
| 营销运营 | 优惠券、兑换码、广告位、推荐位、消息与推送 | 无资金和支付密钥权限 |
| 商家客服 | 工单、用户基本资料和相关订单只读 | 不可修改用户资产与订单状态 |
| 数据分析员 | 仪表盘、报表和获授权导出 | 全部只读 |

商家所有者可新建自定义角色、选择权限点并分配员工。员工不能授予自己未拥有的权限。

### 3.3 权限结构

权限由四部分组成：

1. **资源**：如剧目、订单、提现、员工、支付配置。
2. **动作**：查看列表、查看详情、新建、编辑、提交审核、审核、发布、停用、导出等。
3. **数据范围**：平台全部、指定商家、当前商家、本人创建的数据。
4. **条件**：数据状态、金额阈值、是否涉及密钥或个人信息。

建议权限编码使用 `域.资源.动作`，例如：

- `platform.merchant.create`
- `platform.content.publish`
- `finance.withdrawal.confirm_transfer`
- `content.drama.update`
- `merchant.order.export`
- `merchant.push.send`

“审核通过”和“驳回”、“申请提现”和“确认打款”、“查看支付配置”和“查看密钥”必须拆成不同权限点。

## 6. 简洁仪表盘

### 6.1 总后台仪表盘

首屏最多保留以下内容：

- 核心指标卡：活跃商家、今日新增用户、今日播放用户、今日订单金额、峰值在线。
- 时间对比：每项支持今日、昨日、本月，金额按币种分组，不把不同币种直接相加；可附基准币种估算但必须标注“估算”。
- 趋势图：新增用户、播放、订单、收入，默认 7 天，可切 30 天。
- 排行：商家收入/播放排行、热门剧目排行，各显示前 5。
- 待办：待审内容、待审提现、异常支付回调、超时工单、即将到期商家/内容授权。
- 系统状态：构建、推送、导入、存储/CDN 等关键任务异常数量；无异常时不占大面积。

平台员工只看到其权限范围内的卡片；例如内容审核员不展示收入明细，财务不展示无关社区治理数据。

### 6.2 商家仪表盘

- 核心指标卡：今日新增用户、播放用户、付费用户、订单金额、当前在线。
- 趋势图：用户、播放、转化、收入，默认 7 天。
- 热门内容：播放、完播、付费排行前 5。
- 待办：待完善/被驳回内容、未处理评论举报、提现进度、超时工单、推送失败、配置缺失。
- 快捷入口：新增剧目、批量导入、创建活动、申请提现；仅按权限显示。

## 7. 关键工作流

### 7.1 商家创建、到期与恢复

1. 超级管理员创建商家，填写基本资料、默认语言/币种、到期时间和负责人。
2. 系统创建商家所有者账号，分配平台子域名，初始化默认角色和配置。
3. 商家配置品牌、域名、存储、支付、短信/邮件和推送；每项独立测试并显示状态。
4. 到期前按规则提醒平台与商家。
5. 到期后商家后台进入只读/可导出状态，用户端暂停服务，异步任务不再新增。
6. 总后台延长到期时间后恢复服务，保留原数据、配置和日志。

商家启停、到期时间变化和恢复均要求填写原因并写入审计。

### 7.2 自定义域名

1. 商家提交域名。
2. 系统给出 DNS 记录并自动验证所有权。
3. 验证通过后申请证书并进行连通性检查。
4. 商家请求设为默认域名；切换前校验 HTTPS、回调地址和租户绑定。
5. 旧域名保留短期回退，切换和回退均记录操作者。

禁止仅凭请求 `Host` 头确定租户；域名必须来自平台维护的已验证绑定表。

### 7.3 白标应用与热更新

1. 商家维护品牌资料并提交；总后台审核名称、图标、启动图、包标识和域名。
2. 总后台选择目标平台和环境创建构建任务，证书/签名密钥仅平台安全岗位可管理。
3. 构建完成后提供测试包和安装记录；通过测试后由总后台发布正式版本。
4. 资源热更新支持可选、强制、灰度、暂停和回滚；每次发布记录版本、变更说明和覆盖范围。
5. 涉及原生能力的变化必须发整包；iOS 更新必须遵守商店规则。

### 7.4 代理商私有内容自主发布

1. 代理商保存草稿并上传封面、剧集，系统校验媒体归属和就绪状态。
2. 代理商点击“确认上架”，无需总部审批；未来发布时间进入“待定时上架”。
3. 代理商可自行下架，系统取消该剧及剧集的旧定时任务，保留已购权益。
4. 下架后可编辑并重新上架；发布、下架及编辑均保留版本、幂等和审计。
5. 历史待审记录可撤回旧审核为草稿；总部不再提供私有内容审核和社区治理入口。

### 7.5 公共内容授权

1. 平台创建单剧授权或内容包，设置商家、开始时间和到期时间。
2. 商家仅可对有效授权内容设置可配置项并上架，不能改写平台源内容。
3. 到期前提醒；到期时自动停止新购买并下架，已有订单权益按授权规则处理。
4. 延期后可恢复原上架配置，授权变更全程可追溯。

### 7.6 支付与订单

- 商家可选择自有支付通道或平台公共通道；订单创建时固化商家、通道、币种、金额、商品快照和计价规则。
- 支付回调必须验签、幂等处理并记录原始回调摘要；后台不能手工把未支付订单直接改为已支付。
- 多币种价格由商家分别手动设置，列表和报表不跨币种直接求和。
- 支付密钥默认掩码展示；查看、修改、测试均单独授权并审计，日志不得保存明文密钥。

### 7.7 平台代收提现

1. 平台通道收款成功后生成商家结算明细，区分待结算、可提现、冻结和已提现。
2. 商家财务输入金额并提交提现申请，系统冻结相应可提现余额。
3. 平台财务审核；驳回时资金解冻并填写原因。
4. 审核通过后线下打款，上传凭证并确认完成。
5. 金额、收款账户或状态变更不得直接覆盖原记录，使用追加流水和冲正记录。

审核与确认打款宜由不同权限完成；即使同一人兼任，也必须分两步确认。

### 7.8 后台退款

用户端不提供退款申请入口。获授权管理员从订单详情发起退款，系统校验可退金额、通道能力和订单状态，要求填写原因。退款经通道处理后追加退款记录和资金流水，不修改原支付事实；失败可重试但必须保证幂等。

### 7.9 消息与推送

1. 商家选择站内信或已配置的 Android/iOS 推送，设置目标人群、语言、跳转和发送时间。
2. 系统先估算人数并执行频率、退订、禁用账号和内容合规检查。
3. 高人数群发要求二次确认，可由权限策略要求复核。
4. 发送任务异步执行，展示成功、失败、退订和无有效设备数量，支持安全重试。

### 7.10 工单与平台介入

用户提交工单后由所属商家分配、回复、关闭或重开。平台默认只读监管，遇到升级或超时可介入；平台回复必须带“平台客服”身份，内部备注对用户不可见。所有状态变化形成时间线。

## 8. 表单与交互原则

- **状态可见**：页面顶部明确展示草稿、待审、已发布、已驳回、已停用、只读等状态，以及状态原因和下一步。
- **草稿优先**：长表单支持自动保存或手动存草稿；“保存”和“提交审核/发布”分开。
- **按主题分区**：商家、剧目、支付等大型详情使用概览页加标签页，避免一个超长表单。
- **默认最少字段**：主表单只展示常用字段，高级设置折叠；不因扩展能力让日常页面变复杂。
- **多语言一致**：固定字段与翻译字段分开；显示各语言完成度，缺失时按商家默认语言回退。发布前明确提示缺失语言，不静默生成翻译。
- **币种准确**：金额使用最小货币单位存储；输入时显示币种、小数位和最终扣款预览。
- **时间明确**：数据库统一 UTC，后台按商家时区展示；定时发布/到期表单同时标注时区。
- **敏感信息保护**：手机号、邮箱、收款账户、支付密钥默认脱敏；查看完整值需要专门权限并记录。
- **危险操作确认**：停用商家、下架、退款、打款、群发、强退设备等必须展示影响范围，要求二次确认；资金和平台级操作要求填写原因。
- **不可硬删除**：订单、资金流水、审核、授权、工单和审计日志禁止硬删除；普通内容使用软删除并支持一级恢复。
- **批量任务可追踪**：导入、导出、群发、构建等转为异步任务，提供进度、错误文件、发起人、参数摘要和结果。
- **错误可处理**：错误信息说明失败对象、原因和建议操作；批量任务允许下载失败明细，不因一条错误丢失全部成功项。
- **列表可复用**：筛选条件写入 URL，支持保存常用视图；重置筛选不清除商家上下文。

## 9. 审计原则

### 9.1 必须记录的事件

- 登录、失败登录、登出、强制下线、角色与权限变化。
- 商家创建、启停、到期/恢复、域名和品牌变化。
- 内容提交、审核、发布、下架、恢复和授权变化。
- 支付配置、密钥更新、订单异常处理、退款、余额、提现和打款。
- 用户封禁、设备下线、个人信息查看、注销处理。
- 群发消息/推送、活动发布、导入、导出和构建发布。
- 万能验证码开关、白名单、失效时间及每次实际使用。

### 9.2 日志字段

至少包含：事件 ID、时间、操作者 ID/角色、所属平台或商家、目标资源及 ID、动作、结果、原因、请求追踪 ID、IP、设备/浏览器、变更前后差异摘要。敏感值只记录“已变更”及密钥版本，不记录明文。

### 9.3 审计可靠性

- 审计日志仅追加，不允许后台编辑或删除；设置独立保留策略和访问权限。
- 平台进入商家视角、跨商家查询和导出必须额外标识。
- 导出文件设置有效期和下载权限；记录筛选条件、字段范围、生成者和下载者。
- 财务流水、支付回调与业务订单使用关联 ID，可从任一记录追溯完整链路。
- 管理接口返回可供支持人员定位的追踪 ID，不向页面暴露堆栈或密钥。

## 10. 前端落地约束

- 路由元数据声明所需权限点、可用主体类型和页面数据范围；服务端返回授权菜单，前端只负责展示与交互控制。
- 公共页面组件、表格、筛选器、审核时间线、异步任务和审计差异组件全平台复用。
- 平台与商家同名资源可复用页面骨架，但接口和数据范围必须明确区分，避免用前端隐藏字段实现隔离。
- 所有页面必须处理“无权限、商家已到期、配置缺失、任务处理中、数据已变化”五类状态。
- 权限变化后刷新令牌或强制重新获取权限；已打开页面在提交操作时以后端最新权限为准。
- 页面和接口权限点从同一权限清单生成或校验，防止菜单、按钮和 API 长期不一致。
