# QQ SMTP 测试发信

仅针对 Night Flix 的独立测试服务器，不使用闪创环境或邮件密钥。

## 配置

代理商后台「邮箱与短信验证码」选择 QQ SMTP，填写已开启 SMTP 的 QQ 发件地址和 16 位授权码。
使用账号别名时先验证该别名能登录 SMTP。凭据仅加密入库、不回显、不写日志，不能提交 Git。
系统固定连接 `smtp.qq.com:465`，校验证书且至少 TLS 1.2，不接受租户自定义连接地址或关闭 TLS。
邮件通过现有独立 worker 投递，保留验证码哈希、短期投递载荷加密、限流和租户隔离。

保存后保持停用；向自己控制的邮箱发送一次测试，渠道测试通过后才可启用。
“测试通过/sent”仅表示 SMTP 服务接受邮件，不证明进入收件箱，仍需收件人确认。
SMTP 不提供 API 级幂等保证；重试使用相同 Message-ID，但异常重试可能收到重复邮件。
QQ 邮箱是测试方案，不能保证固定发送配额或无限发送。不要开放无速率限制的群发功能。

Resend 与 QQ 可在同一代理商的邮件配置中切换，每次切换会提升版本、停用并清空测试状态，
旧版本队列任务被拒绝。数据库迁移 `0040_qq_smtp_communications.sql` 保留租户、配置 ID、
渠道和创建者不可变，仅允许邮件供应商随停用的新版本切换。

## 发布验证

本地 API 完整回归：127 文件，822 通过、1 个原有原生构建测试跳过。
新增 8 个 SMTP 边界测试和 1 个数据库渠道切换/投递回归；后台状态测试 3 项通过，API/后台类型检查通过。
本地 QQ 身份验证成功（未发送邮件），测试服务器到 QQ 的 TLS 证书验证成功。
公网真实投递、启用和收件确认结果在发布完成后另行记录。

构建仅在本地进行，使用 `build-artifact.mjs`；上传制品并核对 SHA256 后解压新 release。
迁移前备份，迁移后启动隔离候选进程并验证，再切 current 和重启四个独立服务。
首次测试配置只通过代理商受控 API 写入，不将授权码复制到服务器明文文件。

若回退到不支持 QQ SMTP 的旧版：先通过 API 停用 QQ 配置，确认 worker 没有正在投递的 QQ 任务，
再切回已验证的旧制品并重启。此增量迁移可保留；不要回灌整库覆盖之后的用户数据。
